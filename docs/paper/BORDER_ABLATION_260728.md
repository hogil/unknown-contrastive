# palette 전처리 ablation — 마커·배경·경계 중 무엇을 지울까 (260728)

## 질문

grouping 할 때 wafer palette PNG 에서 **결함 grade(0~7) 말고 무엇을 지워야 성능이 좋은가?**

지울 후보가 셋이다. 한 번에 하나씩만 벗겨서 **각각의 기여를 분리**했다.

| | 이름 | `UC_PALETTE_MASK` / `UC_PALETTE_MODE` | 남기는 index | ①에서 뺀 것 |
|---|---|---|---|---|
| ① | 일반 이미지 (원본) | `0` / — | 전부 | — |
| ④ | 칩경계 통일 + 배경유지 | `1` / `grade_bg` | 0~7 + 경계10 + 배경8 | **컬러 마커** |
| ② | 칩경계 통일 + 배경삭제 | `1` / `grade_only` | 0~7 + 경계10 | + **배경** |
| ③ | 칩경계 삭제 + 배경삭제 | `1` / `grade_noborder` | 0~7 만 | + **경계** |

"통일"은 파랑·초록·노랑·자주 같은 **컬러 마커(11~23)가 전부 흰색이 되고 회색 격자(10)만
남는다**는 뜻이다.

전처리 결과 샘플: [`BORDER_ABLATION_260728_samples/`](BORDER_ABLATION_260728_samples/)

## 설정

| 항목 | 값 |
|---|---|
| **subset** | **5개, 완전 disjoint** — class 마다 `[s*20 : (s+1)*20]` 슬라이스. 겹침 0장 확인 |
| subset 크기 | **42 class × 20장 = 840장** |
| 제외 class | `Thick-Edge_fork` (50장뿐이라 5×20=100 을 못 채움) |
| backbone | `convnextv2_base.fcmae_ft_in22k_in1k_384` (frozen, head 없음) |
| 다이얼 | mcs ∈ {6, 10}, ms=3, leaf, eps=0.06 |
| reassign | `nearest_q90` |
| 채점 | `--offline-eval` (폴더명 = 정답 라벨) |
| 총 셀 | **4 조건 × 5 subset × 2 다이얼 = 40** |
| 잡음폭 | noise ±2.28pp, ARI ±0.019, Hom ±0.005, Comp ±0.033 |

`Thick-Edge_fork` 를 뺀 이유: 그냥 두면 subset 3·4 에서만 그 class 가 사라져 **P1 분모가
달라지고** subset 간 비교가 성립하지 않는다. 빼면 남은 42 class 가 전부 200장 이상이라
5개 subset 의 class 구성이 완전히 동일하다.

## 결론

1. **범인은 컬러 마커(idx 11~23)다.** ①→④ 만으로 ARI +0.21, **10셀 전부 잡음폭 밖**.
   흰색 비율은 55.4% → 55.5% 로 **0.1%p** 밖에 안 바뀌는데 이만큼 오른다 —
   아주 작은 고대비 픽셀이 임베딩을 지배하고 있었다.
   (마커 12~23 은 거의 모든 class 에 공통으로 나타난다. 클래스 정보를 흘리는 게 아니라
   **클래스와 무관한 고대비 변동**이라 결함 패턴을 가린다.)

2. **배경(idx 8)도 지우는 게 낫다.** ④→② 로 ARI +0.052, 10셀 중 8셀 잡음폭 밖 / 6셀 플러스.
   효과는 마커의 1/4 이고 s0mcs6 처럼 반대로 가는 셀도 있지만 방향은 플러스다.

3. **경계(idx 10)는 남겨라.** ②→③ 은 ARI −0.049, **10셀 중 9셀이 마이너스**.
   회색 격자는 shortcut 이 아니라 chip 크기·정렬을 알려주는 **쓸모 있는 구조 신호**다.

4. **채택: `UC_PALETTE_MASK=1` + `UC_PALETTE_MODE=grade_only`** (= ②, 현재 기본값).

### ⚠ 단일 pool 결과에서 정정된 것 2건

pool 1개(43 class 860장)로 먼저 냈던 결론 중 둘이 **5 subset 에서 뒤집혔다.**

| 항목 | 단일 pool 결론 | 5 subset 결론 |
|---|---|---|
| 배경 제거 | "무의미" (승자가 다이얼마다 +1/−3/+1) | **이롭다** (+0.052, 8/10 잡음폭 밖) |
| P2 noise | "① 원본이 최고 (1.35)" | **② 가 최고** (① 2.79±0.88 vs ② 1.76±0.41) |

①의 P2 표준편차가 0.88 로 크다 — 단일 pool 이 우연히 낮은 쪽에 걸렸던 것이다.
따라서 "마스킹은 P1 을 위해 noise 를 희생한다"는 앞선 설명은 **틀렸다.** 둘 다 좋아진다.

### ⚠ anchor 기록과의 상충

anchor pool 기록에는 "경계 idx10 을 남기면 이득의 대부분이 사라진다 → 지워라"가 있었다.
여기서는 정반대다(9/10 셀에서 지우면 손해). 두 pool 의 차이를 가르지 못했으므로
**pool 마다 다시 재는 것**이 맞다.

## ★★ 무라벨 지표가 정반대를 가리켰다

단일 pool(43 class 860장) 기준:

| 순위 | seed_noise 최소 (무라벨) | 실제 P1 최대 (라벨) |
|---|---|---|
| 1 | **① 원본 (11.74)** | **② (28/37)** |
| 2 | ③ (14.88) | ④ / ③ (25/37) |
| 3 | ② (17.79) | ① 원본 (19/37) |
| 4 | ④ (20.12) | — |

**순위가 완전히 뒤집혔다.** `argmin(seed_noise)` 로 골랐다면 **가장 나쁜 ①** 을 골랐다.
seed_noise 최악인 ④(20.12)가 라벨로는 상위권이다.

이유는 분명하다. 마스킹은 이미지를 서로 비슷하게 만들어 HDBSCAN 이 자신 없는 점을
noise 로 더 뱉는다. seed_noise 는 올라가지만 **남은 클러스터의 품질은 훨씬 좋아진다**.

### 함의 — 무라벨 선택 규칙의 적용 범위

`argmin(seed_noise)` 는 **레시피/epoch 선택**(같은 입력, 같은 전처리, encoder 만 다름)에서
검증된 규칙이다. **입력 전처리를 바꾸는 축에는 쓰면 안 된다.**

- Rule C (epoch 선택), step3 셀 선택 → 전처리 고정이므로 계속 유효
- palette 마스킹 on/off 결정 → **seed_noise 로 고르지 마라.**
  라벨 있는 pool 에서 정하고 그 설정을 이식하거나, 사내에서 소량이라도 라벨을 확보해 정하라.

step1 의 `frozen_masked` arm 은 seed_noise 만 보고하므로 **그 숫자로 마스킹을 판단하면 틀린다.**
(240장 pool 에서 frozen 23.33 vs frozen_masked 27.08 로 마스킹이 나빠 보였지만 라벨로는 반대.)

## 곁가지로 잡은 버그 — 캐시 키 충돌

`deploy/build_cache.py` 의 캐시 키가 `(파일목록, IMG, palette_mask 불린)` 뿐이었다.
`grade_only`·`grade_bg`·`grade_noborder` 는 **픽셀이 다른데 키가 같아** 같은 캐시를 공유했다.
그대로 돌렸으면 ②③④가 전부 같은 결과로 나왔을 것이다 — 이 실험 자체가 무의미해진다.

→ 키에 `UC_PALETTE_MODE` 를 넣고, spawn 워커에도 모드를 **명시적으로** 전달하도록 고쳤다.
검증: 4조합 키가 전부 다르고 캐시 픽셀도 실제로 다르다
(raw↔unify 608,641 / raw↔noborder 1,322,749 / unify↔noborder 833,399 /
keepbg↔raw 158,709 / keepbg↔unify 455,359 / keepbg↔noborder 1,263,591).

## 한계

- **seed 1개.** subset·다이얼은 흔들었지만 HDBSCAN bootstrap seed 는 42 고정이다.
- **arm 마다 다이얼을 다시 고르지 않았다.** 규칙상 각 arm 을 자기 최적점에서 비교해야
  하는데, 공통 다이얼 2개에서 결론이 유지되는 것으로 대신했다.
- **합성 데이터다.** 사내 실데이터의 마커·경계 구성이 다르면 재측정해야 한다.
  특히 사내 데이터에 컬러 마커가 없다면 이 실험의 주된 이득(+0.21)도 없다.
- 40셀 전부 `--offline-eval` 로 폴더명을 정답으로 썼다. 폴더명이 진짜 라벨이 아니면 무효다.
