# palette 전처리 ablation — 마커·배경·경계를 어떻게 할까 (260728)

## 질문

grouping 할 때 wafer palette PNG 에서 **결함 grade(0~7) 말고 무엇을 어떻게 처리해야
성능이 좋은가?** 한 번에 하나씩만 바꿔서 **각 단계의 기여를 분리**했다.

| 단계 | 하는 일 | `UC_PALETTE_MODE` |
|---|---|---|
| 1 | 원본 그대로 | `raw` (mask off) |
| 2 | 칩경계색 마커(11~30)를 **기본 칩경계색(10)으로 통일** | `unify_border_bg` |
| 3 | + 배경(8)을 **흰색으로 제거** | **`unify_border`** |
| 4 | + 칩경계(10)까지 **흰색으로 제거** | `grade_noborder` |

★ 2단계는 마커를 **지우는 게 아니라 회색으로 바꾼다.** 흰색으로 지우면 그 자리의 칩경계가
끊긴다 — **경계 픽셀의 10.2%가 마커**라 격자에 구멍이 생긴다 (실측 15장:
경계 10,478,708px = 회색(10) 89.8% + 마커(11~30) 10.2%).

전처리 결과: [`BORDER_ABLATION_260728_samples/`](BORDER_ABLATION_260728_samples/)
(`ladder4_crop_zoom2x.png` = 칩 2×2 2배 확대, `ladder4_crop_1to1.png` = 칩 4×4 원본 픽셀)

## 설정

| 항목 | 값 |
|---|---|
| **subset** | **5개, 완전 disjoint** — class 마다 `[s*20 : (s+1)*20]`. 겹침 0장 확인 |
| subset 크기 | **42 class × 20장 = 840장** |
| 제외 class | `Thick-Edge_fork` (50장뿐이라 5×20=100 을 못 채움) |
| backbone | `convnextv2_base.fcmae_ft_in22k_in1k_384` (frozen, head 없음) |
| 다이얼 | mcs ∈ {6, 10}, ms=3, leaf, eps=0.06 |
| reassign | `nearest_q90` |
| 채점 | `--offline-eval` (폴더명 = 정답 라벨) |
| 총 셀 | **6 조건 × 5 subset × 2 다이얼 = 60** |
| 잡음폭 | noise ±2.28pp, ARI ±0.019, Hom ±0.005, Comp ±0.033 |

`Thick-Edge_fork` 를 뺀 이유: 그냥 두면 subset 3·4 에서만 그 class 가 사라져 **P1 분모가
달라지고** subset 간 비교가 성립하지 않는다. 빼면 남은 42 class 가 전부 200장 이상이라
5개 subset 의 class 구성이 완전히 동일하다.

## 결과 — 4단계 사다리 (10셀 평균 ± 표준편차)

| 단계 | `UC_PALETTE_MODE` | P1 (/36) | P2 noise | P3 Comp | P4 Hom | ARI |
|---|---|--:|--:|--:|--:|--:|
| 1 원본 | `raw` (mask off) | 23.9 ± 3.2 | 2.79 ± 0.88 | 0.9522 ± 0.0216 | 0.8243 ± 0.0236 | 0.5460 ± 0.0749 |
| 2 마커→기본 칩경계색 | `unify_border_bg` | 27.8 ± 4.4 | 2.39 ± 0.51 | 0.9580 ± 0.0231 | 0.9093 ± 0.0191 | 0.7701 ± 0.0285 |
| **3 + 배경 흰색제거** | **`unify_border`** | **27.8 ± 3.9** | 1.85 ± 0.59 | 0.9742 ± 0.0164 | 0.9303 ± 0.0154 | **0.8300 ± 0.0270** |
| 4 + 칩경계 흰색제거 | `grade_noborder` | 25.6 ± 3.1 | 1.78 ± 0.50 | 0.9620 ± 0.0185 | 0.8971 ± 0.0206 | 0.7601 ± 0.0485 |

★ **3단계가 P1·P3·P4·ARI 4개 지표 1위.** P2 만 4단계가 0.07 낮은데 잡음폭(2.28) 안이라
차이 없음이다.

## 단계별 기여

| 단계 | P1 | ARI | 잡음폭 밖 | 플러스 |
|---|--:|--:|--:|--:|
| **1 → 2  마커를 기본 칩경계색으로** | +3.9 ± 3.8 | **+0.2240 ± 0.0692** | **10/10** | 8/10 |
| 2 → 3  배경 흰색제거 | +0.0 ± 2.7 | **+0.0599 ± 0.0275** | **10/10** | 5/10 |
| 3 → 4  칩경계 흰색제거 | −2.2 ± 4.0 | **−0.0699 ± 0.0533** | 9/10 | 2/10 |

- **1→2 가 이득의 대부분**(ARI +0.224). 10셀 전부 잡음폭 밖.
- **2→3 은 P1 이 정확히 0** 인데 **ARI 는 +0.060 으로 10/10 잡음폭 밖**이다.
  그룹 개수를 늘리진 않지만 경계를 더 깨끗하게 나눈다.
- **3→4 는 손해.** 10셀 중 8셀이 마이너스. 칩경계는 남겨야 한다.

## ★ 마커: 회색으로 바꾸기 vs 흰색으로 지우기

같은 "마커 제거"라도 **회색 통일(`unify_*`)** 과 **흰색 삭제(`grade_*`)** 는 다르다.
흰색으로 지우면 경계의 10.2%가 끊긴다. 직접 비교했다:

| 비교 | P1 | ARI | 회색 승 | 흰색 승 |
|---|--:|--:|--:|--:|
| 배경 **유지** 상태에서 | +0.7 ± 2.7 | +0.0134 ± 0.0439 | 6/10 | 2/10 |
| 배경 **제거** 상태에서 | −0.9 ± 3.8 | +0.0211 ± 0.0293 | 3/10 | 6/10 |

**ARI 는 양쪽 다 회색이 낫다**(+0.013 / +0.021). P1 은 엇갈린다. 잡음폭(0.019) 경계에
걸쳐 있어 압도적이진 않다.

→ **회색 통일이 방향은 맞지만 효과는 작다.** 큰 이득은 "마커의 원색을 없애는 것"(+0.224)이고,
흰색으로 하든 회색으로 하든 대부분 얻는다. 다만 최종 채택은 ARI 가 더 높고 표준편차가
작은 회색 통일(`unify_border`, 0.8300±0.0270 vs `grade_only` 0.8089±0.0393)이다.

## 결론

1. **범인은 컬러 마커(idx 11~30)다.** 원색을 없애는 것만으로 ARI +0.22, 10셀 전부 잡음폭 밖.
   흰색 비율은 55.4% → 55.4% 로 **전혀 안 바뀌는데**(회색으로 색만 교체) 이만큼 오른다 —
   작은 고대비 픽셀이 임베딩을 지배하고 있었다.
   (마커 12~23 은 거의 모든 class 에 공통으로 나타난다. 클래스 정보를 흘리는 게 아니라
   **클래스와 무관한 고대비 변동**이라 결함 패턴을 가린다.)

2. **배경(idx 8)도 지운다.** P1 은 그대로지만 ARI +0.060, 10/10 잡음폭 밖.

3. **칩경계(idx 10)는 남긴다.** 지우면 ARI −0.070, 8/10 셀 마이너스.
   회색 격자는 shortcut 이 아니라 chip 크기·정렬을 알려주는 **구조 신호**다.

4. **채택: `UC_PALETTE_MASK=1` + `UC_PALETTE_MODE=unify_border`**
   (`deploy/config.py::Cluster.PALETTE_MODE` 기본값으로 반영).

### ⚠ 앞선 결론에서 정정된 것 3건

| 항목 | 이전 | 지금 |
|---|---|---|
| 채택 모드 | `grade_only` (마커 흰색삭제) | **`unify_border`** (마커 회색통일) — ARI 0.8089 → 0.8300 |
| 배경 제거 | 단일 pool 에서 "무의미" | **이롭다** (ARI +0.060, 10/10 잡음폭 밖) |
| P2 noise | 단일 pool 에서 "① 원본이 최고" | **마스킹이 최고** (① 2.79±0.88 vs ③ 1.85±0.59) |

①의 P2 표준편차가 0.88 로 커서 단일 pool 이 우연히 낮은 쪽에 걸렸던 것이다.
따라서 "마스킹은 P1 을 위해 noise 를 희생한다"던 앞선 설명은 **틀렸다** — 둘 다 좋아진다.

### ⚠ anchor 기록과의 상충

anchor pool 기록에는 "경계 idx10 을 남기면 이득의 대부분이 사라진다 → 지워라"가 있었다.
여기서는 정반대다(8/10 셀에서 지우면 손해). 두 pool 의 차이를 가르지 못했으므로
**pool 마다 다시 재는 것**이 맞다.

## ★★ 무라벨 지표가 정반대를 가리켰다

단일 pool(43 class 860장) 기준:

| 순위 | seed_noise 최소 (무라벨) | 실제 P1 최대 (라벨) |
|---|---|---|
| 1 | **① 원본 (11.74)** | ② `grade_only` (28/37) |
| 2 | ③ `grade_noborder` (14.88) | ④ / ③ (25/37) |
| 3 | ② `grade_only` (17.79) | **① 원본 (19/37)** |
| 4 | ④ `grade_bg` (20.12) | — |

**순위가 완전히 뒤집혔다.** `argmin(seed_noise)` 로 골랐다면 **가장 나쁜 ①** 을 골랐다.
seed_noise 최악인 ④가 라벨로는 상위권이다.

이유는 분명하다. 마스킹은 이미지를 서로 비슷하게 만들어 HDBSCAN 이 자신 없는 점을
noise 로 더 뱉는다. seed_noise 는 올라가지만 **남은 클러스터의 품질은 훨씬 좋아진다**.

### 함의 — 무라벨 선택 규칙의 적용 범위

`argmin(seed_noise)` 는 **레시피/epoch 선택**(같은 입력, 같은 전처리, encoder 만 다름)에서
검증된 규칙이다. **입력 전처리를 바꾸는 축에는 쓰면 안 된다.**

- Rule C (epoch 선택), step3 셀 선택 → 전처리 고정이므로 계속 유효
- palette 마스킹 결정 → **seed_noise 로 고르지 마라.**
  라벨 있는 pool 에서 정하고 그 설정을 이식하거나, 사내에서 소량이라도 라벨을 확보해 정하라.

step1 의 `frozen_masked` arm 은 seed_noise 만 보고하므로 **그 숫자로 마스킹을 판단하면 틀린다.**
(240장 pool 에서 frozen 23.33 vs frozen_masked 27.08 로 마스킹이 나빠 보였지만 라벨로는 반대.)

## 곁가지로 잡은 버그 — 캐시 키 충돌

`deploy/build_cache.py` 의 캐시 키가 `(파일목록, IMG, palette_mask 불린)` 뿐이었다.
`grade_only`·`grade_bg`·`unify_border`·`grade_noborder` 는 **픽셀이 다른데 키가 같아**
같은 캐시를 공유했다. 그대로 돌렸으면 모든 마스킹 조건이 같은 결과로 나왔을 것이다 —
이 실험 자체가 무의미해진다.

→ 키에 `UC_PALETTE_MODE` 를 넣고, spawn 워커에도 모드를 **명시적으로** 전달하도록 고쳤다.
검증: 조합별 키가 전부 다르고 캐시 픽셀도 실제로 다르다
(raw↔unify 608,641 / raw↔noborder 1,322,749 / unify↔noborder 833,399 /
keepbg↔raw 158,709 / keepbg↔unify 455,359 / keepbg↔noborder 1,263,591).

## 한계

- **seed 1개.** subset·다이얼은 흔들었지만 HDBSCAN bootstrap seed 는 42 고정이다.
- **class 수 1가지(42).** class 수를 바꾸면 결론이 달라지는지 미확인 — 다음 실험.
- **arm 마다 다이얼을 다시 고르지 않았다.** 공통 다이얼 2개에서 결론이 유지되는 것으로 대신했다.
- **합성 데이터다.** 사내 실데이터의 마커·경계 구성이 다르면 재측정해야 한다.
  특히 사내 데이터에 컬러 마커가 없다면 주된 이득(+0.22)도 없다.
- 60셀 전부 `--offline-eval` 로 폴더명을 정답으로 썼다. 폴더명이 진짜 라벨이 아니면 무효다.
