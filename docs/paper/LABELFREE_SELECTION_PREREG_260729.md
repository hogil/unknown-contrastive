# 무라벨 레시피 선택 규칙 — 사전등록 (260729)

**이 문서는 clean546 replication 스윕이 끝나기 전에 작성됐다.** 결과를 보고 기준을
고르면 post-hoc 이라 증거가 되지 않는다. 작성 시점: 9셀 중 3셀 완료(base/neg060/neg085),
나머지 6셀 미채점.

## 검증 대상 규칙

> 라벨 없이 `argmin(seed_noise)` 로 레시피 셀을 고른다.

## 정답 기준 (pre-registered) — 하나만 쓴다

**P1 > P2_noise > P3_comp > P4_hom 의 사전식(lexicographic) 비교.**
잡음폭 밖에서만 차이로 인정한다: noise ±2.28pp / Comp ±0.033 / Hom ±0.005 / ARI ±0.019.

**★ argmax(ARI) 는 정답 기준이 아니다.** 이건 임의 선택이 아니라 사용자가 이미 못 박은
우선순위다 — memory `feedback_priority_p1_to_p4` ("P1 class_capture_rate, P2 noise_pct,
P3 Completeness, P4 Homogeneity … 불량 1개라도 group 으로 나오는 게 제일 중요, recall 느낌").
ARI 를 쓰면 결론이 실제로 뒤집힌다: clean546 기존 20셀에서 ARI 는 n86x(0.8592)를 고르지만
n86x 는 P2 에서 lr40 에 7.4pp(3.2 밴드) 진다 — 즉 ARI 는 **우리 우선순위 기준으로 더 나쁜
셀**을 집는다. 두 기준이 갈릴 때는 사용자가 정한 P1-P4 를 따른다.

## 판정 방법

1. 라벨 없이 `argmin(seed_noise)` 로 1셀을 고른다.
2. 라벨을 공개해 사전식 승자를 구한다.
3. 둘이 같으면 적중(HIT), 다르면 실패(MISS).
4. **동시에 winner→#2 seed_noise 격차(밴드 수)를 기록한다** — 아래 가설 때문.

## 사전 등록 가설 — "이건 랭커가 아니라 이상치 탐지기다"

기존 증거는 규칙이 **1위만 맞추고 중간 순위는 무의미**함을 보인다:
- severstal mcs20: 순위상관 rho = +0.00. argmin 은 lr008 을 맞췄으나 2순위로 고른
  neg060 은 실제 ARI 0.2768 로 최하위권.
- 격차 구조: severstal 승자→2위 = 8.34pp(**3.7 밴드**), 나머지 8셀은 8.6pp 안에 뭉쳐
  구분 불가인데 그 ARI 는 0.152~0.611 로 흩어져 있다.
- clean546 기존 20셀(rc): 승자→2위 = 5.68pp(**2.5 밴드**).

**가설 H:** argmin 이 2위와 **약 2밴드 이상** 벌어져 있을 때만 신뢰할 수 있고,
상위 셀들이 1밴드 안에 뭉쳐 있으면 이 규칙은 정보가 없다.

**이번 스윕에서의 사전 예측:** 승자→2위 격차가 2밴드 이상이면 HIT, 1밴드 이내로
뭉치면 MISS 가 나와도 규칙 실패가 아니라 **H 가 예측한 무정보 구간**으로 해석한다.
(이 해석 규칙도 결과 보기 전에 여기 적어 둔다.)

## ★ 별건 발견 — LR 이 두 pool 모두 **탐색 경계**에서 이겼다

| pool | LR 그리드 | 승자 |
|---|---|---|
| severstal | {lr002, base(4e-3), **lr008**} | **lr008 = 최댓값** |
| clean546 (기존 20셀) | base×{0.25, 0.5, 2, **4**} | **lr40 = 최댓값** |

두 도메인 모두 **가장 높은 LR 에서 최고**다 = 최적점을 찾은 게 아니라 **그리드 끝에 닿은
것**이다. 위쪽이 한 번도 시험된 적이 없다. LR 은 `_crossds_leaderboard.md` 에서 이미
미탐색 1순위로 지목됐고 260726 에 clean546 에서 실행까지 됐는데 **어느 문서에도 기록되지
않아** HANDOFF/GOAL_AND_LADDER 는 아직도 "LR 미탐색"으로 적혀 있다.

**다음 실험(사전등록):** LR 축을 위로 연장한다 — clean546 lr80/lr160, severstal lr016/lr032.
각 셀은 선택 규칙의 추가 시험점이기도 하다(공짜).

## 이 규칙으로 할 수 있는 것 / 없는 것

- ✅ **레시피·epoch 선택**(입력 고정, 학습 설정만 비교)에 쓴다.
- ❌ **전처리 선택에 쓰면 안 된다** — `docs/paper/BORDER_ABLATION_260728.md:132-142` 에서
  argmin(seed_noise) 는 palette 모드 순위를 **정확히 거꾸로** 매겼다.
- ❌ **자동 게이트로 승격 금지** — `docs/ABSOLUTE_RULES.md` §7: 무라벨 지표는 어떤 것도
  최종 판정이 될 수 없고 "먼저 볼 후보 정렬" 용도로만 쓴다. 사내엔 정답이 없어서
  이 규칙 자체를 검증할 방법이 없기 때문이다. 산출물은 "무엇을 배포할지"가 아니라
  **"무엇을 먼저 눈으로 볼지"** 다.
